# Kafka consumer offset management

_Generated 2026-06-20_

95% of Kafka implementations I've seen get consumer offset management wrong, and it's a recipe for disaster in production me. When a consumer fails or is restarted, its offset is lost, causing data duplication or loss. To avoid this, you need to manually manage offsets using the `_offsets` topic or a custom solution. I prefer using a custom DB to store offsets, it gives me better control scale pe.

```java
Properties props = new Properties();

props.put("key.deserializer", "org.springframework.kafka.support.serializer.ErrorHandlingDeserializer");
props.put("value.deserializer", "org.springframework.kafka.support.serializer.ErrorHandlingDeserializer");
```

In my experience, using `auto.offset.reset` is not a reliable solution, as it can lead to data loss or duplication. Instead, I recommend using `seek` and `commit` methods to manually manage offsets. This approach gives you finer control over data processing and ensures that your application is fault-tolerant.
