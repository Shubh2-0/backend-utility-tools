# Kafka consumer offset management

_Generated 2026-06-09_

95% of Kafka implementations I've seen are using auto-reset offset management, but what happens when your consumer crashes and you're left with duplicate messages? In production me, this can be a nightmare to deal with. To avoid this, I always recommend manual offset management. It gives you fine-grained control over your consumer's offset, allowing you to handle failures and duplicates with ease. 

Here's an example of how you can manually commit offsets in Kafka:
```java
KafkaConsumer<String, String> consumer = new KafkaConsumer<>(properties);
consumer.subscribe(Collections.singleton("my-topic"));
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(100);
    for (ConsumerRecord<String, String> record : records) {
        // process the record
    }
    consumer.commitSync(Collections.singletonMap(new TopicPartition("my-topic", 0), new OffsetAndMetadata(10)));
}
```
