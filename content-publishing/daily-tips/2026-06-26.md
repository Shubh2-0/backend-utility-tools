# Docker multi-stage builds for Spring Boot

_Generated 2026-06-26_

95% of Spring Boot developers are still using single-stage Docker builds, and that's a huge mistake. When it comes to building efficient and scalable Docker images for Spring Boot applications, multi-stage builds are the way to go. Not only do they reduce the final image size, but they also improve build times and simplify the debugging process. 

In a multi-stage build, you can separate the build and runtime environments, which means you can use a larger image for building and a smaller one for runtime. For example, you can use a JDK image for building and a JRE image for runtime:
```java
FROM openjdk:17-jdk-alpine AS build
WORKDIR /app
COPY . /app
RUN ./mvnw clean package

FROM openjdk:17-jre-alpine
WORKDIR /app
COPY --from=build /app/target/my-app.jar /app/
CMD ["java", "-jar", "my-app.jar"]
```
This approach not only reduces the image size but also improves security by excluding unnecessary build tools from the final image.
