# REST API versioning strategies

_Generated 2026-06-07_

80% of REST API versioning strategies are a mess, and it's time to clean them up. I've seen many APIs using URI-based versioning, like `/v1/users`, but this approach can lead to tight coupling between the client and server. A better approach is to use header-based versioning, where the client specifies the desired version in a custom header, like `Accept: application/vnd.alignbits.v1+json`. This way, the same URI can serve different versions of the API.

```java
@RestController
@RequestMapping("/users")
public class UserController {
    @GetMapping
    public ResponseEntity<String> getUsers(@RequestHeader("Accept") String acceptHeader) {
        if (acceptHeader.contains("v1")) {
            // return v1 response
        } else if (acceptHeader.contains("v2")) {
            // return v2 response
        }
    }
}
```
