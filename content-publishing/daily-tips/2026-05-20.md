# When to use Spring WebFlux

_Generated 2026-05-20_

95% of the time, I see Spring WebFlux being misused in production me, and it's mainly because developers don't understand when to use it. Let's set the record straight - WebFlux is not a replacement for Spring MVC, it's a different tool for a different job. If you're building a traditional, synchronous web application, stick with Spring MVC, but if you're dealing with asynchronous, non-blocking I/O operations, WebFlux is the way to go. 

For example, when handling a large number of concurrent requests, WebFlux can help improve performance by using Project Reactor under the hood. Here's a simple example of how to create a WebFlux endpoint:
```java
@Bean
public RouterFunction<ServerResponse> routes() {
    return RouterFunctions.nest(path("/users"),
            RouterFunctions.route(
                    GET("/{id}"),
                    this::getUser
            )
    );
}

private Mono<ServerResponse> getUser(ServerRequest request) {
    // logic to get user
}
```
