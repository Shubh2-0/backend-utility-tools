# Structured logging in Spring Boot

_Generated 2026-06-14_

95% of logs in production me are useless because they're not structured. As a backend engineer, I've seen this firsthand, and it's frustrating when you're trying to debug an issue and can't make sense of the logs. Structured logging in Spring Boot can be a game-changer - it allows you to log data in a JSON format that's easily parseable by log aggregators like ELK or Splunk. To get started, you can use a library like Logback or Log4j and configure it to output JSON logs. For example:
```java
logging:
  pattern:
    console: "%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n"
  file:
    name: logs/application.log
```
However, to take it to the next level, you can use a custom logger that adds additional context to your logs, like the request ID or user ID. This can be achieved by creating a custom Logger class that wraps the underlying logger and adds the additional context.
