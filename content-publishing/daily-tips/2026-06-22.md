# Spring Profiles in production

_Generated 2026-06-22_

95% of Spring Boot applications I've seen in production are not using Spring Profiles to their full potential. I still see hardcoded configs and env-specific hacks, which can be a nightmare to maintain. In production me, it's crucial to separate configs for different environments. Spring Profiles allow you to do just that - define a set of beans that are specific to a particular environment. For example, you can have a `dev` profile for local development and a `prod` profile for production. 

```java
@Profile("dev")
@Bean
public DataSource dataSource() {
    return DataSourceBuilder.create()
            .driverClassName("com.mysql.cj.jdbc.Driver")
            .url("jdbc:mysql://localhost:3306/mydb")
            .username("root")
            .password("password")
            .build();
}

@Profile("prod")
@Bean
public DataSource dataSource() {
    return DataSourceBuilder.create()
            .driverClassName("com.mysql.cj.jdbc.Driver")
            .url(System.getenv("DB_URL"))
            .username(System.getenv("DB_USERNAME"))
            .password(System.getenv("DB_PASSWORD"))
            .build();
}
```
By using Spring Profiles, you can easily switch between different environments without having to change your code. So, are you using Spring Profiles in your production-grade applications, and if not, what's holding you back, scale pe?
